AMBATUDRONE TEENSY 4.1 DATA LOGGER
==================================

PURPOSE
-------
This logger records the motor microphone and ESC-input current at the same
instant. It is separate from the Arduino Mega flight controller, Python bridge,
and ESP32 Bluetooth relay.

Do not add SD-card writing to the Mega motor-control loop. A slow SD write must
never delay a kill command or motor failsafe.


FINAL DATA PATH
---------------

Microphone OUT --------> Teensy A2
ACS758 VIOUT ----------> Teensy A3
                         Teensy 4.1
                              |
                              v
                    Built-in 32 GB microSD

Each test produces:

  RUN0001.WAV   Channel 1 = microphone, channel 2 = current sensor
  RUN0001.JSON  Calibration, clipping, dropped samples, and run information

The channels are sampled together at 48,000 samples/second with 12-bit ADC
readings stored in a 16-bit stereo WAV container.


CURRENT SENSOR PLACEMENT
------------------------
The Amazon B0832PHKB5 board is an ACS758LCB-050B bidirectional +/-50 A sensor.

For one ESC:

  Battery positive ----> ACS758 IP+
  ACS758 IP- ----------> ESC positive power input
  Battery negative ----> ESC negative power input

Low-voltage signal wiring:

  ACS758 VCC ----------> Teensy 3.3 V
  ACS758 GND ----------> Teensy GND
  ACS758 VIOUT/OUT ----> 1 kohm resistor ----> Teensy A3
                                                |
                                                +-- 6.8 nF capacitor --> GND

Current flowing from IP+ to IP- produces a positive current reading.

IMPORTANT:

  - Do not place this sensor in any of the three motor phase wires.
  - Do not carry ESC current through a solderless breadboard or Dupont wire.
  - Use high-current wire/connectors sized for the motor and ESC.
  - Keep the high-current conductors short and mechanically secured.
  - The low-voltage VCC/GND/OUT pins are isolated from the high-current path,
    but the sensor's signal GND must connect to Teensy GND.
  - Put a 0.1 uF ceramic bypass capacitor from ACS758 VCC to GND close to the
    board if the module does not already contain one.

The 1 kohm / 6.8 nF input filter has a cutoff near 23 kHz. This matters because
the sensor itself has roughly 120 kHz bandwidth, while a 48 kHz logger cannot
represent frequencies above 24 kHz without aliasing.

If you have a 4-in-1 ESC, one sensor before the ESC measures the combined current
of all four motor channels. For motor-health data, run one motor at a time so
the current trace belongs to a known motor. To distinguish four motors running
together, you would need separate per-channel current measurements.

The +/-50 A range is suitable for a one-motor bench trial only if that motor
stays below 50 A. A complete four-motor power system can exceed this range.


MICROPHONE PLACEMENT AND WIRING
-------------------------------
Mount the microphone so its sound port is 7.5 mm from the motor base:

  - Use a rigid, repeatable 7.5 mm bracket or spacer.
  - Point the microphone opening toward the motor base/bearing area.
  - Keep the microphone out of the propeller and loose-wire path.
  - Use a thin rubber/foam isolation layer under its PCB so arm vibration does
    not completely dominate the airborne sound measurement.
  - Start with the amplifier at its lowest gain. At 7.5 mm, clipping is likely
    if the gain starts high.

The Amazon microphone ASIN is indexed as part of a generic electret-amplifier
family, but its exact voltage/output variant is not exposed reliably. Inspect
the board label and use the matching case below.

CASE A: MAX4466-style 2.4-5.5 V analog microphone

  Microphone VCC ------> Teensy 3.3 V
  Microphone GND ------> Teensy GND
  Microphone OUT ------> 1 kohm resistor ----> Teensy A2
                                                |
                                                +-- 6.8 nF capacitor --> GND

CASE B: LM386-style 4-12 V analog microphone

  Do not connect this module directly to A2. An LM386 board is a speaker power
  amplifier, not a 3.3 V ADC microphone preamplifier. Its output coupling and
  voltage swing vary among the generic boards. Use a MAX4466-style microphone
  module for this logger, or provide a clear photograph/schematic so a safe
  AC-coupled, 1.65 V-biased input circuit can be designed for the exact board.

If the board markings or listing do not clearly identify the microphone supply
and output range, do not connect OUT yet. Send a clear photograph of both sides
of the board first.


SMALL SIGNAL PARTS TO HAVE
--------------------------

  2 x 1 kohm resistors
  2 x 6.8 nF ceramic/film capacitors
  1 x 0.1 uF ceramic capacitor for ACS758 supply bypass, if not on the module

These parts are only for the low-voltage sensor outputs. They do not carry
motor or ESC current.


MICROSD CARD
------------
Use the 32 GB microSD card in the Teensy 4.1 built-in card slot.

  1. Format it FAT32.
  2. Insert it before powering the Teensy.
  3. Use a Class 10/U1 or better card.
  4. Safely stop a recording before removing power or the card.

The logger writes about 192,000 bytes/second:

  10 seconds = about 1.92 MB
  30 seconds = about 5.76 MB
  32 GB       = roughly 44-46 hours of raw recording

Short 10-30 second labeled trials are recommended.


UPLOAD THE TEENSY CODE
----------------------
File:

  AmbatuDrone_Teensy_Logger.ino

Using Arduino IDE 2 on Windows:

  1. Install Teensy support from PJRC/Teensyduino.
  2. Open AmbatuDrone_Teensy_Logger.ino.
  3. Select Tools > Board > Teensy 4.1.
  4. Select USB Type > Serial.
  5. Leave CPU Speed at 600 MHz.
  6. Compile and upload.

The sketch uses the ADC, IntervalTimer, SD, and SPI libraries supplied with the
Teensy environment. Make sure Arduino is using the Teensy SD library, not a
separately installed generic SD library.


RECORD A TEST
-------------
Initial checkout should be done with propellers removed.

  1. Connect the Teensy over USB.
  2. Open Serial Monitor at 115200 baud and Newline line ending.
  3. Keep every motor off.
  4. Send:

       zero

  5. Confirm current_zero_valid=1 in:

       status

  6. Start recording:

       start

  7. Run the desired motor test.
  8. Stop and finalize the files:

       stop

An optional momentary button from Teensy pin 2 to GND also toggles start/stop.
The built-in LED is on while recording.

The logger automatically stops after 120 seconds.


SERIAL COMMANDS
---------------

  help     Show commands
  status   Show SD, calibration, queue, and dropped-sample state
  zero     Measure zero-current offset; every motor must be off
  start    Begin recording
  stop     Finalize and close the current recording


CHECK DATA QUALITY
------------------
After a run, open RUNxxxx.JSON.

Good first-run checks:

  dropped_frames          should be 0
  adc_error_count         should be 0
  microphone_clip_count   should be 0 or very small
  current_clip_count      should be 0

If microphone_clip_count is large, lower microphone gain or move the
microphone farther from the motor. Do not compare healthy/faulty recordings
made with different microphone distances or gain settings.

If current_clip_count is nonzero, stop the test. The sensor is reaching the
edge of its measurable range or the signal wiring is wrong.


EXTRACT AUDIO AND CURRENT ON WINDOWS
------------------------------------
Copy both RUNxxxx.WAV and RUNxxxx.JSON into the same folder as:

  extract_motor_run.py

Run:

  py extract_motor_run.py RUN0001.WAV

No third-party Python packages are required.

Outputs:

  RUN0001_audio.wav
  RUN0001_current.csv

The CSV contains:

  sample_index
  time_s
  current_A
  current_adc
  microphone_adc


WHAT DOES NOT CHANGE
--------------------
These existing files stay responsible for control and Bluetooth:

  droneControl4Motor.py
  bridgeMotorControl_Bluetooth.ino
  AmbatuDrone_ESP32_Bluetooth_Bridge.ino

Servo functionality remains dormant. The Teensy logger neither controls the
motors nor changes the Mega failsafe.
